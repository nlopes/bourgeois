= Fancy animation and input performance

== Physical trial status

Both the partial-redraw optimization and its full-scene replacement have physical black-screen reports and are withdrawn.
Restore the preserved original Fancy image before further host experiments.
The owner completed that restoration and confirmed the scene appeared again.
The subsequent isolated frame-interval and controller trials both worked physically and form the current default source.

The partial-redraw optimization passed QEMU checks but produced a black screen on the physical host.
Linux still started automatically after roughly 30 seconds.
That image is withdrawn: the host installer, enrollment command, and one-time selector reject it, while removal remains available.
The exact firmware-specific cause has not been established.
See xref:host-fancy.adoc#_withdrawn_optimization_and_recovery[restoration of the previously working image].

== Current working baseline

Fancy redraws the complete scene after each input poll, using a 17-millisecond frame budget instead of the original 40 milliseconds.
The initial cadence-only module changed by exactly two bytes encoding those interval constants.
The confirmed controller fix was then added without changing the graphics loop or hourglass.
The owner confirmed that this isolated build worked on the physical host.
A fresh build from the repository's restored default source reproduced its exact full-file and Authenticode hashes.
The code keeps the original hourglass, pose cadence, and `PAUSED` label.
Repeated arrows now preserve walk progress and facing at a gate.
Input permanently cancels the 30-second timer for that visit.

The interval permits up to about 59 FPS when drawing fits the budget.
Physical FPS has not been measured.
The owner reported that walking and changing direction felt mostly unchanged from the original.
The faster frame budget alone therefore has not delivered the intended perceived improvement.
The VM's observed result was about 37 FPS; the exact timing method is recorded below.
The animation, sand, partial redraw, and profiling changes remain separate experiments.
The withdrawn `bourgeois_fps` override is absent from the restored default source.

The graphics calls use GRUB's https://www.gnu.org/software/grub/manual/grub-dev/grub-dev.html#Video-API[Video API].
The inspected Ubuntu source's `grub-core/video/efi_gop.c`, `grub_video_gop_swap_buffers`, calls firmware to present its complete shadow buffer.
Drawing and firmware presentation time both limit the achievable frame rate.

== Isolated cadence trial

After restoration of the original image succeeded physically, `build/fancy-cadence` was built from that renderer with only the frame interval changed from 40 to 17 milliseconds.
The native module differs by exactly two bytes and keeps its original size.
The EFI core sections and PE section sizes are unchanged; the only embedded file content that differs is `bourgeois.mod`.
This retains the original hourglass, pose cadence, controls, and rendering path.

The Secure Boot VM checks passed trusted acceptance, untrusted and tampered rejection, 1440p rendering at both gates, courtyard restoration, and Esc.
The routing fixture passed cancellation beyond 30 seconds, immediate L/W, Space after arrival, and untouched automatic Linux selection.
The last run produced 1,153 frames over 31,158 milliseconds measured by the harness, about 37.0 FPS.
This uses the host monotonic clock because the original renderer lacks the newer `scene_ms` counter; it is not directly the same clock as the historical GRUB timing measurements above.
The original gate-facing behavior was retained in the cadence-only experiment.
The owner then tried this image physically and confirmed that it worked.
The separate trial preserved the normal distribution boot path.
Its subsequent controller correction is now included in the default source; broad withdrawn changes remain separate.

== Reproduce the working baseline checks

Use the source, prerequisites, snapshots, and Secure Boot VM dependencies from xref:host-fancy.adoc[the host trial guide].
Build and benchmark the restored default source:

[source,shell]
----
make test
make host-fancy-stage HOST_FANCY_STAGE=build/fancy-controller-default
make host-fancy-benchmark HOST_FANCY_STAGE=build/fancy-controller-default HOST_FANCY_EVIDENCE=build/fancy-controller-default-check
----

Use fresh stage and evidence directory names when artifacts already exist.
The default benchmark uses `--original-timing` for the confirmed source and also checks repeated-arrow facing.
It checks cancellation beyond 30 seconds, immediate L/W, Space after arrival, and the full untouched timer.
The timer sample records frame count and FPS using the host monotonic clock, without adding profiling code to the EFI image.
Tracing is enabled only in the disposable VM; staged host configuration keeps tracing disabled.
Results are written to `trusted/input-checks.json` and `trusted/debug.log`.

The checker also captures both gates, compares the intervening courtyard to detect trails, checks Esc, and verifies shim rejection of untrusted and altered images.
Repeated-arrow facing comparisons are enabled by `--original-timing` for the controller trial or `--benchmark` for the historical profiling builds.
The detailed `--benchmark` mode requires the newer profiling fields absent from the current working source.
The fixture entries print routing markers; they do not boot physical operating systems.
Inspect actual GRUB captures as well as automated results.
`make test` passes 82 Python checks and the C controller and layout checks.
The default controller test includes the repeated-arrow and facing regressions.
The README recording uses this confirmed build; local identity and trust details are omitted from published results.
