= Implementation notes

== Target

The development preview targets Ubuntu 24.04 x86_64 UEFI.
The lab uses Ubuntu cloud image `20261017` and GRUB `2.12-1ubuntu7.3`.
Secure Boot and actual Windows boot validation remain deferred.
The Windows entry prints `BOURGEOIS_WINDOWS_FIXTURE` and returns to the menu.
It does not install or boot Windows.

== Entry ownership

The generator reads Ubuntu's current `grub.cfg` after `update-grub`.
It keeps support commands and the selected entry bodies.
It changes each selected title and hotkey while retaining its ID, classes, and authentication options.
It removes other menu blocks from the nested slim scene.
A `true` command replaces removed blocks so enclosing conditionals remain valid GRUB syntax.
Missing, duplicate, unsafe, and nested submenu IDs fail generation.
`grub-script-check` validates both the scene and the parent configuration before use.

The parent retains Ubuntu's advanced kernels, recovery entries, editor, and command line.
The hook runs after menu entries have been defined.
It preserves one-shot selection for `boot_once=true`.
For `recordfail=1`, it shows the technical menu with no timer.
Slim uses nested `configfile`; Esc returns to the parent with no timeout.
The hook reinitializes `gfxterm` and sets explicit text colors for the technical menu.
Fancy sets the selected ID as `default` and sets `timeout=0`, then returns to GRUB's native menu executor.
GRUB keeps responsibility for authentication and execution.
A returned boot failure stays in the native menu and does not re-run the scene.

== Graphics and input

Both editions use `courtyard-nameplates.png`, which has raised masonry and recessed stone-framed nameplates based on the original concept.
The OS names are part of that artwork; GRUB does not draw name labels over the gates.

Slim uses stock `boot_menu`, `label`, and `circular_progress` facilities.
Its sand image is static; the ring and seconds label reflect GRUB's live timer.
The title and countdown labels have dark text shadows.
The two-row menu uses stock GRUB nine-slice pixmaps for a centered gold-trimmed panel, a gold selected row with dark text, and a dark outlined unselected row.
The panel fits the longest title plus small text insets, row borders, and its decorative frame.
Small generated gold ornaments and a dark footer follow the Slim concept mockup.
GRUB paints the theme canvas in reverse declaration order, so shadow components follow the text they back.
Up/Down and Enter use GRUB's normal behavior.
The letter shortcuts are the native lowercase `l` and `w` hotkeys.

The optional `tools/host_theme.py` builder uses stock GRUB class icons for a static traveler at the selected door.
A clipped one-row menu view scrolls to the selected entry's icon while the ordinary two-entry list stays visible.
A transparent full-screen list makes GRUB repaint nested menu coordinates correctly when the selection changes.
The icon canvases must match the display resolution supplied to the builder.
The existing host entries must have Ubuntu or GNU/Linux classes and a Windows class.
This builder omits the lab's L/W shortcut hint because it does not modify those entries.
It generates a scaled DejaVu Sans Mono PF2 font for the host menu and includes its font notices.
Pillow measures the Linux and Windows titles at that font size to set the panel width.
Ubuntu's theme header loads that font; the temporary preview loads it explicitly.
Its separate `gfxterm` background hook keeps the courtyard behind boot messages; themes alone do not set that terminal background.
The operating system can change the display after taking control.

Slim preserves the distribution's `gfxmode` instead of forcing a low resolution.
Fancy also inherits `gfxmode`, with `bourgeois_gfxmode` as an explicit override.
The largest usable mode must be verified with `videoinfo` in the machine's actual GRUB session.
Where the signed GRUB image omits that diagnostic, keep Secure Boot enabled and use a mode verified by a hardware trial.

`tools/host_gpu.py` inspects display-class PCI devices, `boot_vga`, bound drivers, and DRM connector status through Linux sysfs.
Optional `lspci` supplies human-readable model names; the inspection works with PCI IDs when it is absent.
It recommends an adapter from boot/display evidence and reports unknown or ambiguous cases explicitly.
The selection only prints monitor-cabling and UEFI setup guidance.
It cannot change which firmware GOP adapter stock GRUB selects or prove that a Linux-advertised mode is available in GRUB.
Both editions use the firmware's preboot graphics output.

Fancy owns a polling loop through GRUB's terminal input API.
A Left or Right press selects a walking destination; the character completes the walk without requiring key release events.
The opposite arrow reverses direction at the current position.
The center-to-gate trip takes about 1.2 seconds.
Space commits only at a gate, and L/W commits immediately.
Fancy accepts both lowercase and uppercase shortcuts.
Any key cancels automatic boot for that visit.
The draining hourglass uses the same remaining-time value as automatic Linux selection.
The walking destinations use the measured door centers from the artwork.
The contextual Space prompt identifies the gate the character has reached.
The hourglass has an open wood-and-brass frame, curved glass, and falling grains.
Its sand moves by pixel area so the two bulbs track the remaining time.
Dark text outlines keep the title and controls readable without backing panels.
The native renderer scales the background and sprite strip using nearest-neighbor interpolation.
It frees its bitmap allocations and restores the previous video mode before returning.
It then initializes `gfxterm` so the technical menu remains visible after direct GOP rendering.
The terminal is explicitly restored to the full display, and `background_image --mode=stretch` reapplies the courtyard before GRUB executes the selected entry.
Background restoration errors are reported without suppressing the boot choice.
The native image includes `gfxterm_background` alongside its renderer dependencies.

Fancy uses the same DejaVu UI family as the host Slim theme, with PF2 sizes 20 through 120 built in the guest.
Its scale follows display height, constrained by width for narrow modes and capped at the available font sizes.
Text outlines, hourglass details, and control offsets scale together.
The original composition, free-standing timer, moving hero, and contextual prompts remain distinct from Slim's two-row list.
The 20-pixel font is loaded first and selected for the recovery terminal before loading larger UI fonts.
This avoids a large fallback font making the technical menu unusable at smaller resolutions.

== Lab boundary

The tools install only into the disposable VM reached with the lab's SSH key.
They do not change the Mac's boot files or EFI variables.
The fancy preview uses a separate EFI file on the lab VM's EFI partition and leaves Ubuntu's EFI image intact.
This is a development preview, not a real-machine installer.

== Native build

The module is compiled against the matching Ubuntu GRUB source and generated headers.
The preview combines that module with Ubuntu's existing module set using `grub-mkstandalone`.
It embeds the native module in a separate EFI executable.
No change to GRUB's core input or menu executor is required.
The normal Ubuntu EFI executable remains the slim and recovery boot path.
The module's explicit dependency list is scoped to the pinned Ubuntu build and checked by booting the resulting image.
The local preflight checks VM tools without requiring host GRUB binaries or host font packages.
Native builds reject an uninitialized or stopped guest before waiting for SSH, and display the guest build log on compilation failure.

The update hook reads `/boot/grub/grub.cfg.new` after Ubuntu has emitted its normal entries.
This temporary-file convention is specific to the supported Ubuntu `grub-mkconfig` version.
Other distributions require validation before using the hook.

The module advertises `feature_bourgeois=1` when it loads and clears the flag when it unloads.
The hook checks this flag before calling the scene.
GRUB's `insmod` command returns zero even when a module cannot be loaded, so its return status cannot serve as that check.
