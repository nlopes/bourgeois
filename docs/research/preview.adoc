= Run and recover the development preview

== Prerequisites

Use Python 3.11 or newer, a C compiler, Make, QEMU, xorriso, and OpenSSH.
Start with `make vm` and `python3 tools/lab.py wait`.
The first native build also installs Ubuntu build dependencies and downloads the matching GRUB source inside the guest.
It takes longer under x86 software emulation on an ARM Mac.

== Editions

[source,shell]
----
make slim
python3 tools/lab.py reset
----

For fancy, boot Linux in the current preview so SSH is available, then run:

[source,shell]
----
make native-build
make fancy
make vm-stop
make vm
----

The tools register a separate `bourgeois preview` EFI entry inside the lab VM.
`make fancy` puts it first in the guest boot order.
`make slim` selects Ubuntu's original EFI entry.
`reset` performs a cold VM restart with the selected guest boot order.

== Controls

[cols="1,2,2",options="header"]
|===
|Action |Slim |Fancy
|Move or choose |`l` / `w` snaps the hero to a door |Left/Right walks to a gate
|Boot chosen OS |Space, or Enter |Space at a gate
|Boot immediately |Space at the selected door |`l` / `w`, also uppercase
|Technical menu |Esc |Esc
|Timer |Any input cancels |Any input cancels
|===

Use `python3 tools/lab.py key left`, `key spc`, `key l`, or `key esc` to send QEMU keys.
Capture the display with `make screenshot`.
The lab is headless by default.

== Recovery and removal

Esc opens the full Ubuntu menu with no timer.
Use `e` to edit an entry, `c` for the command line, or Advanced options for recovery kernels.
If the native module or artwork is unavailable, the parent menu remains available.
One-shot boots and Ubuntu's failed-boot path skip the scene.

To remove the preview inside the lab guest:

[source,shell]
----
python3 tools/lab.py ssh 'sudo rm -f /etc/grub.d/99_bourgeois /etc/grub.d/41_windows_fixture /etc/bourgeois.json; sudo update-grub'
----

Before removal, run `make slim` to select Ubuntu's original EFI entry.
The separate `/boot/efi/EFI/bourgeois/grubx64.efi` file and its firmware entry can then be removed inside the guest.
The files under `/boot/grub/bourgeois/` and `/usr/local/lib/bourgeois/` can be removed after the hook is gone.
To discard the lab, stop the VM and remove `build/vm/`.
The next start creates a fresh overlay and SSH key from the checked image cache.

This repository provides a disposable development preview.
Native EFI installation, signed EFI packaging, and actual Windows validation in the lab need a separate validation step.

== Host artwork for an existing menu

The host tools are separate from the VM installers.
They require Python 3.11 or newer, Pillow, Make, sudo, `update-grub`, and `grub-script-check`.
The builder writes only to the chosen staging directory.
The generated theme expects the existing two-entry Linux/Windows menu and its native classes.
The current host uses `/boot/grub/clean-menu.cfg`; this is a local convention, not a standard Ubuntu file.
The builder does not install the lab fixture, a menu hook, a native module, or an EFI image.

[source,shell]
----
make host-stage
make test
----

`HOST_SIZE` defaults to `1280x720`; `HOST_STAGE` defaults to `build/host-theme-review`.
The direct staging command is `python3 tools/host_theme.py build/host-theme-review --size 1280x720`.
The builder records file checksums and display dimensions in `manifest.json`.
Build for the actual GRUB resolution, because the transparent class icons use that pixel width.
The stock two-entry menu stays usable if another mode is selected, but the hero positions will not match the doors.
Check firmware modes with `set pager=1` and `videoinfo` at GRUB's command line.
Linux monitor modes alone do not establish which modes the firmware exposes to GRUB.

Install or reinstall the already-present host theme with:

[source,shell]
----
make host-install
----

This target builds as the current user and runs `tools/host_install.py install` with sudo.
The installer requires the existing Bourgeois theme and executable `99_clean_menu` generator.
It rejects a conflicting lab menu hook, modified staging files, and clean-menu boot commands that differ from the full menu.
It backs up the theme directory, its background hook, its own settings override, `grub.cfg`, and `clean-menu.cfg` under `/var/backups/bourgeois/slim-*`.
Keep the printed backup path.

It installs only the reviewed artwork and `06_bourgeois_background`, and selects the theme and display mode through `/etc/default/grub.d/zzzz-bourgeois-host.cfg`.
It leaves other defaults, menu generators, kernel arguments, EFI files, and firmware entries alone.
It runs `update-grub`, checks both menus, and verifies their boot commands still match.
If those steps fail, it restores the backed-up files and returns an error.
Reboot only after the command succeeds.
The installer does not reboot the machine.

The background hook initializes only the terminal background after Ubuntu's header; it does not replace boot entries.
The installed `preview.cfg` remains available as a temporary GRUB configuration using the existing clean-menu commands.
Do not treat `grub-mkconfig -o` to another path as a dry run: local generator hooks may still write live auxiliary files.

Restore the most recent successful installation's backup with:

[source,shell]
----
make host-rollback
----

`BACKUP` defaults to `/var/backups/bourgeois/latest` and can select an older printed backup directory.
Rollback restores the theme, background hook, and installer-owned settings, then regenerates both menus for the currently installed kernels.
If regeneration fails, it restores the snapshot's generated menus and returns an error; check the failure before rebooting.
Retain local keyboard access and recovery media; automatic recovery from a failed operating-system boot or power loss is not provided.
Fancy remains a VM preview until its GRUB version, disk layout, and Secure Boot signing are adapted and validated for the host.

== Tests and packages

[source,shell]
----
make test
make boot-test
make dist
----

`make boot-test` restarts the configured VM and sends real keyboard events.
It tests cancellation, shortcuts, Esc tools, and automatic Linux boot.
Fancy also tests walking and reversal.
Slim also tests repeated door selection without booting and a single Esc after switching.
`python3 tools/boot_test.py fallbacks` checks fancy's asset, module, ID, and display-mode fallbacks.
Inspect the captured editor, command-line, and fallback screenshots as part of review.
Do not run two boot-test processes against the same VM.

`make dist` creates slim and fancy preview archives and `SHA256SUMS` under `build/dist/`.
`make native-build` caches the matching upstream source archives on the host.
Packaging uses those cached files and does not need a running guest.
The fancy archive includes the custom EFI file, the original module source, build scripts, and Ubuntu's corresponding GRUB source archives.
The EFI file embeds the lab's filesystem UUID and must be rebuilt for a different disk.
The archives contain source and development tooling; they are not real-machine installers.
